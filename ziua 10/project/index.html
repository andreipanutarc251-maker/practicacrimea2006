🛡️ HTTP Strict Transport Security

Forțează HTTPS pentru 1 an. Browser-ul nu va accesa niciodată versiunea HTTP, chiar dacă link-ul nu are https://

🚫 Content Security Policy

Blochează injecții de scripturi malițioase. Doar scripturile de pe domeniul propriu pot fi executate.

🔗 X-Frame-Options DENY

Site-ul NU poate fi încadrat în iFrame-uri. Previne atacurile de Clickjacking.

📝 X-Content-Type-Options

Browserul respectă Content-Type declarat. Previne MIME Sniffing attacks.

📋 Antete HTTP de Securitate Active

Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
X-Frame-Options: DENY
X-Content-Type-Options: nosniff
X-XSS-Protection: 1; mode=block
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline'...
Referrer-Policy: strict-origin-when-cross-origin

✅ Checklist de Validare

  • Proiectul este accesibil public printr-un URL securizat SSL
  • Redirecționarea automată de la http:// la https:// este activă (status 301)
  • Fișierul de configurare (netlify.toml / vercel.json) este prezent în rădăcina proiectului
  • Antetele HTTP de securitate sunt transmise corect în răspunsul serverului CDN
  • Certificatul SSL folosește TLS 1.3 cu Perfect Forward Secrecy (PFS)
  • DevTools arată Network tab cu security headers în răspuns
  • CSP și HSTS sunt vizibile în DevTools -> Security

📸 Instrucțiuni pentru Screenshot (SS24_Live_Deployment_Nume.png)

  1. Deschide DevTools (F12) și mergi pe tabul Network
  2. Reîncarcă pagina (Ctrl+R)
  3. Selectează request-ul către pagina principală (index.html)
  4. Mergi pe tabul Response Headers
  5. Screenshot trebuie să arate: URL securizat (https://), lacătul verde, și antetele de securitate
